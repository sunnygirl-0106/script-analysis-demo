### C1 · `services/lock.ts`

删除 `deleteEpisode` 里从 `const index = buildUsageIndex(project)` 到 `nextAssets` 构造的整段，`assets` 原样透传：

```ts
export function deleteEpisode(project: Project, episodeId: string): Project {
  const ep = project.episodes.find((e) => e.id === episodeId)
  if (!ep) return project

  const sceneIds = ep.sceneIds
  const shotIds = sceneIds.flatMap((id) => project.scenes[id]?.shotIds ?? [])

  const nextScenes = { ...project.scenes }
  for (const id of sceneIds) delete nextScenes[id]
  const nextShots = { ...project.shots }
  for (const id of shotIds) delete nextShots[id]

  return {
    ...project,
    episodes: project.episodes.filter((e) => e.id !== episodeId),
    scenes: nextScenes,
    shots: nextShots,
    assets: project.assets,   // ★ v2.0：删集不动资产库。只增不减的删除出口只有项目资产库。
  }
}
```

头注版本抬到 `v2.0`，并把原来那句「资产清理：只删『出场全部落在该集』的资产」整句换成：

```
// 资产：一条都不动。删集只删结构与镜头；本集独有的资产会因为不再被任何镜头挂载
// 而变成「当前剧本未引用」（services/appearanceIndex 的 shotCount === 0），但仍留在库里。
```

`buildUsageIndex` 的 import 在这里就没用了，一并删掉（`resplitScene` 不用它）。

### C2 · `store.deleteScene`

删掉 `const idx = st0.usageIndex()` 到 `.map((a) => a.id)` 整段，以及 `set()` 里的：

```ts
const assets = { ...s.project.assets }
orphanIds.forEach((id) => delete assets[id])
```

`project` 构造里改回 `assets: s.project.assets`。

**toast 文案同步改**（这是用户能看见的口径，比代码更重要）：

| 位置 | 现在 | 改成 |
|---|---|---|
| `deleteScene` | `已删除第 N 场` | `已删除第 N 场（M 个镜头）。项目资产库一条未减，其中 K 项变为「当前剧本未引用」。` |
| `deleteEpisode` | `第 N 集已删除。本集独有的 X 项内容已一并删除，其他剧集使用的内容仍会保留。` | `第 N 集已删除（M 个镜头）。项目资产库一条未减，其中 K 项变为「当前剧本未引用」。` |

## 3. 数据模型改动

### 3.1 `src/data/types.ts` 新增

```ts
/** 剧本分析的流程相位（v2.0）。资产确认是一道闸：分镜在闸之后才存在。
 *  与既有 AnalysisPhase（拆解动画的呈现相位）是两个正交概念，不要合并。 */
export type AnalysisStep = 'import' | 'assetConfirm' | 'storyboard'

/** 用户对一条候选的处理方式（v3 §4.2）。 */
export type CandidateDecision = 'new' | 'link' | 'skip'

/** 待确认候选资产 —— 尚未入库，不进 project.assets。
 *  它没有 promptRevision / deliveredRevision：那两个字段的语义从「入库」那一刻才开始。 */
export interface CandidateAsset {
  tempId: string
  kind: AssetKind
  name: string
  imagePrompt: string
  aliases?: string[]
  /** 角色候选带出的造型（随宿主一起入库或一起丢弃）。 */
  costumeIds?: string[]
  characterId?: string
  /** 原文口径的出现信息。阶段②还没有集/场/镜，只能这么表达。 */
  firstParaNo?: number
  occCount?: number
  decision: CandidateDecision
  /** decision === 'link' 时指向的既有资产 id。 */
  linkTargetId?: string
}

/** 增量确认被打断时挂起的任务，确认完自动续跑（v3 §6.2）。 */
export interface PendingTask {
  kind: 'firstImport' | 'appendEpisode' | 'newScene'
      | 'replaceEpisode' | 'replaceScene' | 'resplitEpisode' | 'resplitScene'
  label: string       // 弹窗标题用，如「追加第 2 集」
  scopeText: string   // 「仅第 2 集原文」
  /** 续跑所需的参数。各 kind 自定，store 里用判别联合取出。 */
  args: Record<string, unknown>
}
```

`Project` 加一个字段：

```ts
export interface Project {
  // …既有字段…
  /** 首次「确认并保存到项目资产库」的时刻。null = 还没入过库。
   *  这是 replaceWholeScript 能力位与阶段②形态（完整确认 / 轻量增量）的唯一判据。 */
  libraryCommittedAt: number | null
}
```

`seed.ts` 的 `seedProject` 里补 `libraryCommittedAt: null`。

> ⚠️ **注意 seed 的语义变了**：现在 `seedProject` 直接给出完整的 assets + shots。v2.0 之后，「首次导入」演示应当从 `libraryCommittedAt: null` + 全部资产在 `candidates` 里 + `shots` 为空 开始。见 §5.3。

### 3.2 不要做的模型改动

- **不要**给 `Asset` 加 `status: 'new' | 'saved'`。原型里那个字段是因为单文件没有第二个容器；仓库里候选和已入库是两个容器（`candidates` vs `project.assets`），加状态位会出现"两个真相源"。
- **不要**给 `Asset` 加 `referenced` 字段。引用态是派生的，`buildUsageIndex(project)[id].shotCount === 0` 就是答案，缓存已经按 project 引用做了记忆化。

## 4. 新增纯函数模块

按仓库方针，会错的规则先写成不碰 UI 的纯函数并配断言。

### 4.1 `src/services/candidates.ts`（规则 R15）

```ts
// 候选资产的抽取与入库。纯函数。
// 规则版本：v2.0（2026-09-01）。断言见 tests/candidates.test.ts 的 R15。
//
// v3 的三层状态在这里落地：
//   项目资产库      = project.assets（只增不减，删除出口只有资产库本身）
//   当前剧本引用    = buildUsageIndex(project) 的 shotCount > 0（派生，不存）
//   待确认新候选    = CandidateAsset[]（本模块）
import { assetKey } from './incremental'

/** 从一批「本次范围内 AI 抽到的资产」里，滤掉库里已有的同名同类项。
 *  判重复用 incremental.assetKey，全系统只此一处判重逻辑。 */
export function extractCandidates(
  project: Project,
  scanned: Array<Pick<Asset, 'kind' | 'name'> & Partial<Asset>>,
): CandidateAsset[]

/** 结算一批候选。
 *  new  → 新建资产入库，promptRevision = 0，deliveredRevision = undefined
 *  link → 不新建，返回 links 供调用方建立引用（本期只用于回执文案）
 *  skip → 什么都不做
 *  已有资产一律不覆盖、不删除。 */
export function commitCandidates(
  project: Project,
  cands: CandidateAsset[],
): {
  project: Project
  added: string[]        // 新入库的资产 id
  linked: Array<{ tempId: string; targetId: string }>
  skipped: string[]
}

/** 同名拦截：候选改名后与库内既有同类资产重名 → 不允许作为新资产入库（v3 R4，倩姐口径）。 */
export function nameConflict(project: Project, cand: CandidateAsset): Asset | undefined
```

**实现要点**

- `commitCandidates` 必须保持既有 `project.assets` 里所有条目的**引用相等**（和 `appendEpisode` 一样的写法），否则 `usageIndexOf` 的记忆化会整体失效。
- 角色候选带 `costumeIds` 时，一并生成对应的 `Look` 资产，`characterId` 指向刚入库的角色 id。
- `nameConflict` 命中时 `commitCandidates` 应把这条降级为 `skip` 并放进返回值，由调用方提示，**不要抛异常**。

### 4.3 扩展 `src/services/staleness.ts`

v3 的「待更新只挂在提示词层」在仓库里**已经有一半了**：`promptStates` 的 `'stale'` 态 + `store.touchPrompt`（改镜头字段 / 挂载 → ready 落回 stale）。本次只补两个触发源：

### 5.3 既有动作的改造

| 动作 | 改造 |
|---|---|
| `appendEpisode2` | 不再直接 `appendEpisode()`。改为：先算 `extractCandidates(project, episode2Payload.assets)` → 有候选就 `openIncrementalGate(..., {kind:'appendEpisode'})`；零候选直接跑。续跑体 = 原来的 `appendEpisode()` 调用 |
| `replaceEpisode` | 同上，`kind: 'replaceEpisode'`。原有「失败不改动原集」的逻辑保留在续跑体里 |
| `resplit` / `resplitEpisode` | 同上，`kind: 'resplitScene' / 'resplitEpisode'`。**补漏口径**：只有 seed 里预置的「首轮漏提」项才产生候选，其余场零候选、不打断 |
| `insertScene` | 空白场：不走闸。填了文本的新场才走（本 demo 里做成两个入口） |
| `insertShot` / `updateShotField` / `setShotDuration` | 不动。已有的 `touchPrompt` 就是 v3 要的行为 |
| `deleteScene` / `deleteEpisode` | 见 §2 C1 / C2 |
| `replaceScript` | 加 `can(project,'replaceWholeScript')` 守卫，为假时 `showToast` 并返回 |
| `updateAssetPrompt` | 之后调 `shotsAffectedByAsset`，把受影响镜头置 `'stale'` |

### 5.4 seed 的两种起点

`analysisStep` 的初值决定 demo 从哪儿开始，两种都要能跑：

```ts
// seed.ts 导出两个入口，App 用 URL query 或常量切换（不做 UI 开关）
export const seedProject: Project           // 已入库 + 有分镜（= 现状，方便直接看分镜表）
export const seedFreshProject: Project      // libraryCommittedAt: null, shots: {}, 全部资产在 candidates

```

默认仍用 `seedProject`（不破坏现有演示与全部既有断言）；`seedFreshProject` 供「首次导入全剧」那条演练与 `AssetConfirm` 页的独立调试使用。

### 7.1 单一真相源：`src/services/drills.ts`

export type LibExpect = 'noloss' | 'same' | 'minus'

export interface DrillRun {
  label: string

  run: (api: DrillApi) => void

  id: string

### 7.3 「是否停下」怎么观测

原型里靠轮询 `S.modal`。React 里不要轮询，用痕迹位：

- `openIncrementalGate` 里 `set((s) => ({ trace: { ...s.trace, sawIncrementalGate: true } }))`

### 7.4 `src/tests/drills.test.ts`

```ts
describe.each(DRILLS)('$group · $op', (drill) => {
  it.each(drill.runs)('$label', (run) => {
    const api = makeDrillApi(freshStore())
    run.arm?.(api)
    const before = api.snapshot()
    run.run(api)
    const after = api.snapshot()
    if (run.expect.lib === 'noloss') expect(after.lib).toBeGreaterThanOrEqual(before.lib)
    if (run.expect.lib === 'same')   expect(after.lib).toBe(before.lib)
    if (run.expect.lib === 'minus')  expect(after.lib).toBeLessThan(before.lib)
    expect(api.get().trace.sawIncrementalGate).toBe(run.expect.gate)
  })
})
```

**这一步是本次改动最大的收益**：原型里靠人点着核对的 22 条规则，进仓库之后变成 CI 里 22 条自动断言。以后谁改了 `deleteScene`，`lib: 'same'` 那条会直接红。

> 演练里凡是要等动画的（`startSplit` 的分步动画），测试里要能跳过。给这些动作加一个 `{ instant: true }` 选项，测试传 true，UI 传 false。

## 10. 移植时最容易踩的六个坑

1. **不要照抄原型的 `render()` 思路**。原型每次操作后整页重绘；仓库是 React，状态变了自然重渲染。原型里那些 `P.render()` 在仓库里一律删掉。
2. **不要把候选混进 `project.assets`**。原型用 `status: 'new'` 是因为单文件只有一个数组；仓库必须两个容器，否则 `usageIndexOf` 的记忆化和 `FIRST_BATCH_KINDS` 的口径全乱。
3. **保持引用相等**。`commitCandidates` / `deleteEpisode` 等所有 project 变换，未受影响的 `scenes` / `shots` / `assets` 条目必须保持原引用——仓库有多条断言直接测这个（R3-③、R6「其他场 shotIds 引用未变」）。
4. **阶段②没有 `shots`**，所以没有 `usageIndex`、没有集场镜、`TabBar` 的 `shot` tab 不该出现。这是原型 v3 最早那版踩过的坑，别在仓库里再踩一次。
5. **别让资产库改动回写分镜**。删资产只标失效，不清 `mounts`；改资产名只改 `assets[id].name`（挂载靠 id 自动跟随，仓库已经是这个设计）。
6. **色调以仓库为准**。原型里的十六进制色值是仓库改色之前的旧值，抄过去等于把调色回滚。

## 11. 一处仍需产品拍板的（不阻塞 P0–P2）

`deleteAsset` 删掉一个**已交付**（`deliveredRevision != null`，下游已出图、已扣星钻）的资产时，要不要额外一道硬确认？

`services/reconcile.ts` 的头注写着「⚠ 绝不自动删除已交付的资产——下游可能已出图、已扣星钻」。那句话说的是"系统不自动删"，与"用户手动删"不冲突，但用户手动删已出图资产仍然是花过钱的操作。

建议：普通资产一次确认；`syncState(a) !== 'draft'` 的资产二次确认，弹窗里写明「该资产已进入出图队列 / 已出图，删除不退还星钻」。等你点头再做。
