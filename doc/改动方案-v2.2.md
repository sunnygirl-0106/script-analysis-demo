# 改动方案 v2.2 · 产品口径优先

> 2026-09-01 · 承接 v2.1。本轮是**产品体验轮**，不是重构轮。
> 执行者请先读第 0 节。凡是「代码这样写更顺」和「产品这样才对」冲突的地方，一律听产品。

---

## 0 · 本轮的四条产品原则（先读，冲突时以此裁决）

**原则一：一个任务 · 一个弹窗 · 一次最终确认。**
用户发起一个创作任务（首次拆分 / 重新拆分 / 添加续集 / 替换本集），系统在**同一个弹窗**里完成资产预检查、设置、消耗展示。发现新资产就把处理选项嵌进当前弹窗，不新开第二个窗。用户只做一次最终确认，系统随后自动"保存资产 → 执行任务"。

**系统内部可以有两步，不能把两步都变成用户按钮。**

**原则二：没有新决策的停顿，一律删掉。**
"资产已保存 → 请点开始拆分"这种中间停顿不给用户任何新信息，只是在暴露系统的执行顺序。删。包括那句 Toast。
反过来：**有新决策的停顿要保留**（比如"这 3 项新资产你要不要存"），因为用户确实要做选择。

**原则三：花钱的动作，价签必须长在按钮上。**
所有会消耗星钻的按钮，文案里直接带价：`确认并开始拆分 · ✦25`。不要把消耗只写在弹窗正文里让用户自己找。

**原则四：生成类动作必须有可见的过程。**
任何"AI 在干活"的动作都不许瞬间出结果。要有分阶段的 loading、要有文案说它在干什么、时长跟工作量正相关。**这是体验，不是性能问题，不要优化掉。**

**本轮不要做的事**：不要加手写断言（口径还在动）；不要重构 store 的状态模型来"顺"（该保留的中间态就保留）；不要抄原型的十六进制色值，只用 `theme.css` 变量。

## 1 · 新增基础设施

这一轮有两样东西是全仓库共用的，先建，后面所有改动都依赖它。

### 1.1 `src/services/cost.ts` —— 星钻计价（新建）

术语统一：仓库里所有「算力」「⚡」全部改成 **「星钻」「✦」**。

```ts
// 演示口径。真实单价等陈硕确认，改这一个文件即可。
export const RATE = {
  parsePerKChar: 2,   // 解析剧本 / 抽资产：每千字 ✦2
  shot: 1,            // 拆分镜头：每镜 ✦1
  assetPrompt: 1,     // 单条资产提示词补全：✦1
  shotPrompt: 6,      // 单镜画面/视频提示词：✦6
} as const
```

需要提供的估算函数（都是纯函数，不碰 UI）：

| 函数 | 用途 |
|---|---|
| `costParse(text: string)` | 按字数估解析消耗 |
| `costSplit(sceneIds, density)` | 按预计镜数估拆分消耗 |
| `costShotPrompts(shotIds)` | 批量提示词 |
| `costAssetPrompt()` | 单条资产提示词 |
| `fmtCost(n)` | 统一渲染成 `✦25` |

**免费的动作，明确不计价**：资产预检查、入库、改名、删候选、挂/解造型、排序搜索、切换 tab。
理由（要写进注释）：预检查不是用户发起的任务，是系统为了保护用户资产库做的自检；对它收费会逼出"先付钱才能看要不要付钱"的死循环。

### 1.2 `src/services/taskRun.ts` + `src/components/TaskProgress.tsx` —— 统一 loading（新建）

**这是本轮体验的核心件，不要图省事跳过。**

`taskRun.ts` 定义阶段脚本（纯数据）：

```ts
export interface Phase { label: string; weight: number }  // weight 决定它占多长
export const PHASES = {
  split:        [{label:'正在保存资产到项目资产库',weight:1},{label:'正在划分集与场',weight:2},
                 {label:'正在拆分镜头',weight:4},{label:'正在生成分镜脚本',weight:3}],
  resplitScene: [{label:'正在保存本次新资产',weight:1},{label:'正在重新拆分本场',weight:4},
                 {label:'正在更新镜头引用',weight:2}],
  resplitEp:    [...], replaceEp: [...],
  appendParse:  [{label:'正在解析第 2 集原文',weight:3},{label:'正在检查尚未收录的资产',weight:2}],
  appendApply:  [{label:'正在保存新资产',weight:1},{label:'正在拆分第 2 集镜头',weight:4}],
  assetPrompt:  [{label:'正在通读全剧原文',weight:2},{label:'正在生成提示词',weight:3}],
  shotPrompt:   [{label:'正在读取镜头内容与 @ 资产',weight:1},{label:'正在生成提示词',weight:4}],
}
```

**时长跟工作量挂钩**（不许写死 500ms）：
```
总时长 = clamp(900 + cost * 130, 1500, 9000)  ms
```
25 镜的拆分 ≈ 4.1 秒，8 镜的重拆 ≈ 1.9 秒，单镜提示词 ≈ 1.7 秒。大活儿明显更久，用户能感觉到量级差别。

`TaskProgress.tsx` 的表现：一列阶段，已完成打 ✓ 变灰，当前项转圈 + 文字高亮，未开始的压到 30% 透明度；底下一条细进度条按 weight 推进。**不显示百分比数字**（假精度），只显示阶段。

## 3 · P2 · 阶段② 资产清单页（`pages/AssetConfirm.tsx`）

### 3.1 删掉「出场」列

表格从 6 列变 4 列：`色点 | 名称 + 提示词 | 状态 | 操作`。
原来的出现次数**降级成名称行下方的第二行小字**：`全剧 7 处 · 首现第 12 段`，点它定位到原文并闪一下（保留现有 `locate()`），hover 整行仍然点亮原文里的名字（保留现有 `enter/leave`）。

腾出来的宽度全部给提示词列——那才是这一页真正要看的东西。

### 3.2 提示词可编辑

- 点提示词区域**行内展开**成 textarea（不要弹窗，这一页已经够重了），失焦或 ⌘Enter 保存，Esc 取消
- 空提示词显示 `✦ AI 结合剧本补全 · ✦1` 按钮，点击后**行内 loading**（用 `TaskProgress` 的紧凑变体，或至少一个转圈 + "正在通读全剧原文…"），约 1.5 秒后落字
- **编辑权限只给本次新增的候选**。已入库的行在这一页只读，鼠标悬停提示"已入库资产请到项目资产库修改"（v3 口径：清单页编辑权限收敛为仅本次新增候选）

### 3.3 角色造型（本轮最大的一块界面欠账）

现在只有一排 chips，要补成原型 `资产清单确认-原型_2.html` 的形态：

- 角色行显示 `3 套造型 ⌄` + `＋ 服装`，点 caret 展开
- 展开后每套造型是一条**子行**，靠一条竖直连接轨归属到上面的角色（不要靠缩进猜），子行有：
  - 造型名 `苏可 · 宽松连帽卫衣`，**自动拼，不单独改名**
  - **自己的提示词**，可编辑，格式是融合式：`苏可素模 + 宽松连帽卫衣的融合造型：…`
  - 操作只有 `⇄ 换服装` / `🗑 解除这套造型`
- 挂载一件服装 = 生成一套造型 + 一条占位提示词，可点 `✦ AI 结合剧本补全 · ✦1`
- 新建的服装同时出现在「服装」tab 里
- 造型子行**没有出现次数**（它跟随角色出现），第二行小字位置留空

### 3.4 工具条替换补录

删掉列表底部那个 `手动补录一个角色…` 输入行。按原型做工具条：

```
[角色 6] [服装 5] [场景 4] [道具 4]      ⌕ 搜索名称、别名或提示词   排序 ▾   ＋ 新增角色
```

- 排序三项：按出现次数 / 按首次出现 / 按名称。**新增的永远置顶**，排序只在同组内生效
- `＋ 新增角色` 开一个小弹窗：名称输入 + 重名拦截 + 提示"先只填名字，加进来之后点 ✦ AI 结合剧本补全"
- 「补录」这个词全仓库清掉，统一叫「新增」

### 3.5 页脚合并成一个动作

页脚只留一个主按钮：

```
确认资产并开始拆分 · ✦25
```

**删掉**"确认并保存到项目资产库"这个独立按钮。
**删掉** `store.commitLibrary` 里那句 Toast：「已保存到项目资产库：入库 19 项。接下来可开始拆分集 / 场 / 镜。」——这句话本身就在教用户"还有第二步"。

**不要**加"仅保存资产，稍后拆分"的弱入口：入库不花钱、拆分也不依赖资产图，"只存不拆"用户拿不到任何好处，只会造出一个"存了没拆"的中间态。

## 4 · P3 · 统一任务弹窗（本轮结构改动）

### 4.1 统一结构

所有创作任务弹窗都长成这样，自上而下：

```
标题：确认资产并开始拆分 / 重新拆分第三场 / 添加第 2 集 / 替换第 1 集

[任务设置区]   镜头节奏、期望镜头数、范围说明……（各任务不同）

[资产检查区]   ← 统一区块 <AssetPrecheck>
[消耗汇总区]   预计生成 25 镜 · 预计消耗 ✦25 · 预计耗时约 1 分钟
               本次生成集 / 场 / 镜及分镜脚本，暂不生成最终提示词
               已有资产及图片不会被覆盖，其他场不受影响

[取消]                              [确认并开始拆分 · ✦25]
```

点主按钮后，**弹窗不关闭**，正文原地替换成 `<TaskProgress>` 跑阶段进度，跑完弹窗关闭 + 一条结果 Toast。
**不要**"关闭弹窗 → 跳整页动画"。整页的 `AnalyzingWorkspace` 从此**只用于首次导入解析**（步骤①，从无到有那一次）。

### 4.2 `<AssetPrecheck>`（新建，四个弹窗共用）

三种状态：

**检查中**（弹窗打开就自动跑，免费）
> ⟳ 正在检查本场是否出现尚未收录的角色、服装、场景和道具……

**没有新资产**
> ✓ 未发现尚未收录的资产，将直接使用项目资产库中的现有资产。

（现在的代码是零候选时静默续跑，用户根本不知道系统查过。必须显式说。）

**发现新资产**
> 发现 3 项尚未收录的资产。以下资产尚未保存，**默认会随本次操作加入项目资产库**。你可以逐项调整处理方式。

| 新识别内容 | 类型 | 处理方式 |
|---|---|---|
| 邻居大姐 | 角色 | `新增到资产库 ▾` |
| 花衬衫 | 服装 | `新增到资产库 ▾` |

区块底部汇总一句：
> 本次将新增 3 项资产到项目资产库，并重新生成第三场分镜。已有资产及图片不会被覆盖，其他场不受影响。

### 4.3 三个处理方式（措辞和行为都要改）

| 现在 | 改成 | 副文案 | 行为 |
|---|---|---|---|
| 作为新资产 | **新增到资产库** | 创建一条新资产，本次及后续分镜都能用 | 现有 `new` 分支不变 |
| 关联已有 | **使用已有资产** | 选一个已有资产替代它 | 见下 ⚠ |
| 忽略 | **本次不入库** | 分镜里保留这段文字，但不形成资产引用、不带图片 | 现有 `skip` 分支不变 |

⚠ **「使用已有资产」现在是个空壳**：`services/candidates.ts` 的 `link` 分支只 push 一条回执，既不写别名也不建引用。而去重是 `kind + 归一化名称` 的精确匹配（`incremental.ts`），"邻居大姐"永远匹配不上"王阿姨" —— 结果就是下次重拆这一场，AI 还会把它当新资产**再问一遍**。

所以 `link` 要真正落地：把候选名写进目标资产的 `aliases`。选择器旁边的副文案要说清后果：

> 以后剧本里再出现「邻居大姐」，也会按「王阿姨」处理。

配套：项目资产库里要能看到这条别名并解除（资产只增不减，但别名必须可撤销，否则误并了没救）。

### 4.4 四个入口的具体形态

**① 首次：确认资产并开始拆分**（`AssetConfirm` 页脚 → 弹窗）
资产检查区不用跑——阶段② 整页本身就是那份检查结果。这里只展示汇总：
> 本次将新增 19 项资产到项目资产库：角色 6 · 服装 5 · 场景 4 · 道具 4。已有资产及图片不会被覆盖。

设置区 = 镜头节奏三选一（复用 `StartSplitDialog` 现有内容）。主按钮 `确认并开始拆分 · ✦25`。
`StartSplitDialog.tsx` 就地改造成这个统一弹窗，别新开文件。

**② 重新拆分本场 / 本集**（`ResplitSceneDialog` / `ResplitEpisodeDialog`）
原文已在库里，弹窗打开即自动预检、免费、毫秒级出结果。一次确认到底。
主按钮 `确认并重新拆分 · ✦8`。

**③ 替换本集 / ④ 添加续集**（`ReplaceEpisodeDialog` / `ScriptImportDialog`）
这两个的原文是用户当场给的，**必须先付费解析才知道有哪些新资产**，做不到"打开弹窗就检查完"。所以在同一个弹窗里分两段，中间有一次**有决策价值的停顿**（符合原则二）：

```
第一段  选择 / 粘贴续集剧本
        [ 解析并检查 · ✦12 ]
          ↓ 弹窗原地跑 PHASES.appendParse
第二段  ✓ 已解析：4 场
        [资产检查区：发现 5 项…]
        [设置区：镜头节奏]
        [消耗：本次还将消耗 ✦32]
        [ 确认并添加续集 · ✦32 ]
          ↓ 弹窗原地跑 PHASES.appendApply → 关闭
```

在第二段点取消：已解析的 ✦12 已消耗不退，剩余不扣，弹窗里要有一行小字说明。

### 4.5 删掉 `IncrementalGateDialog`

`components/IncrementalGateDialog.tsx` + css 删除，`App.tsx` 里的挂载移除。它的内容全部搬进 `<AssetPrecheck>`。

store 侧：`openIncrementalGate` 从"开闸并存住任务等确认"改成"提供一个纯函数 `previewCandidates(scanned)` 供弹窗调用"；`pendingTask` / `cancelIncrementalGate` / 自动续跑随之退役。**注意这是产品结论带来的顺带结果，不是为了简化代码去改的** —— 如果发现某个路径还需要挂起态，保留它，不要为了删而删。

## 7 · 验收（人工点一遍，不配断言）

1. 首次：导入 → 整页解析动画 → 阶段② 清单 → 点一次 `确认并开始拆分 · ✦25` → 弹窗内四段进度 → 直接进分镜表。**全程只点一次确认，没有任何"已保存"提示**
2. 阶段② 表格只有 4 列，没有「出场」列；出现次数在名称下方小字，点了会定位并闪
3. 角色行点 `3 套造型 ⌄` 展开子行，每条造型有自己的提示词，点开能改
4. 右键场 → 重新拆分 → **只弹一个窗**，里面既有节奏设置也有资产检查结果，点一次确认就跑完
5. 没有新资产时，弹窗里明确显示"✓ 未发现尚未收录的资产"
6. 选「使用已有资产 → 王阿姨」，再重拆一次同一场，**不应该再问一遍"邻居大姐"**
7. 每个生成按钮上都有 `✦N`，点下去都有肉眼可见的过程，25 镜的活儿明显比 8 镜的久

## 8 · 需要拍板的开放问题（不阻塞开工）

1. **星钻单价**：`RATE` 现在是演示口径（每千字 ✦2 / 每镜 ✦1 / 提示词每镜 ✦6）。真实单价要问陈硕——PRD 里"费用按什么算"那处空白正好落在这儿
2. **预检查是否真的免费**：本方案按"免费"设计，理由见 1.1。这条口径 v3 里没写，要补进去
3. **别名可撤销**：「使用已有资产」写别名之后，资产库里的解除入口要不要这一轮就做，还是先只写不撤
4. **替换/续集第一段的钱**：取消不退这个口径要产品确认
