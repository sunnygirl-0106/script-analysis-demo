## 一 · 先修 bug：整理剧本页只占半屏

**文件**：`pages/EpisodeOrganize.module.css`（顺手检查 `AssetConfirm` / 其他新页有没有同样问题）

`AppShell` 的 `.contentBody` 是 `display:flex`（横向），`EpisodeOrganize` 的 `.page` 作为它的 flex 子项没有声明 `flex: 1`，
于是按内容宽度收缩，右边一半是空的。

```css
.page {
  flex: 1;            /* ★ 加这一行 */
  min-width: 0;       /* ★ 和这一行 */
  display: flex;
  flex-direction: column;
  height: 100%;
}
/* 顺带：集列表居中限宽，别横着铺满 1800px 的屏 */
.list { max-width: 980px; margin: 0 auto; }
.head, .foot { /* 内部内容同样限宽居中 */ }
.head > *, .foot > * 用一个 .inner 包起来：max-width: 980px; margin: 0 auto; width: 100%;
```

验收：全屏宽度下集列表居中、页脚按钮在列表右边缘对齐，不再半屏。

## 二 · 本轮定下来的产品结论

### 1 · 步骤条收成三步

```
① 整理剧本 → ② 确认资产清单 → ③ 生成分镜脚本 → （分镜页右下角：生成提示词 → 全部就绪后变成「去资产库生图」）
```

「生成提示词」不再是一个步骤：它不换页、不要整页动效，就是分镜表页脚右下角那一个主按钮。全剧提示词生成完后，同一个位置的按钮变成 `去资产库生图 →`。

### 2 · 三处整页动效，每处都跨到下一步

| 触发 | 相位 | 步骤条当前步 | 跑完落到 |
|---|---|---|---|
| 上传弹窗点「开始整理」 | `organizing` | ① | 整理剧本页 |
| 整理剧本页点「确认集数并提取资产」 | `extracting` | **②**（点下去的瞬间就切到②） | 资产确认页 |
| 节奏弹窗点「确认并开始拆分」 | `splitting` | **③**（同上） | 分镜表 |

原则：**动效页属于目标步骤，不属于来源步骤。** 用户点的是「进入下一步」，步骤条就该立刻响应，动效是下一步在干活。

### 3 · 上传必须是一个真实的选文件动作

空态点「上传剧本」→ 弹窗（上传文件 / 粘贴文本 两个 tab）→ 点「开始整理」→ 整页动效 → 整理剧本页。
集数和字数是动效期间「算出来」的，动效结束前页面上不许出现「共 N 集 · X 字」。

### 4 · 节奏选择回到步骤② 的弹窗

v2.4 把三张节奏卡做成了步骤③ 的起点页（`SplitStart`），本轮推翻：改回**在资产确认页点「确认资产并开始拆分」时弹窗**，弹窗样式照竞品截屏（§六）。`SplitStart` 退役。

### 5 · 整理剧本页 ⋯ 菜单照竞品

```
⤒  上传文件 · 解析新集
＋  新建一集
⤓  下载剧本
```

没有「重新上传剧本」。换剧本 = 新建项目，演示里用顶栏「▶ 重新演示」。

### 6 · 资产确认页没有「← 返回整理剧本」

要回去点步骤条 ①。页脚左边只放状态文字，右边一个主按钮。

## 三 · 相位与分派

**文件**：`store/useStore.ts`、`App.tsx`、`layout/AppShell.tsx`

```ts
export type AnalysisPhase = 'empty' | 'organizing' | 'extracting' | 'splitting' | 'done'
```

`App.tsx`：

```

phase organizing/extracting/splitting → FullPageProcess（§四，一个组件按 phase 换文案）

```

store 新增 / 改动：

```ts
startUpload: () => void         // 改：不再直接进 organizing；空态的上传弹窗点「开始整理」才调 beginOrganize
beginOrganize: () => void       // 新：phase 'organizing'
finishOrganize: () => void      // 已有，不动
startExtract: () => void        // 改：set({ analysisPhase: 'extracting', analysisStep: 'assetConfirm' })  ← 步骤条立刻到②
finishExtract: () => void       // 已有；末尾 phase 'done'
beginSplit: (density) => void   // 新：commitLibrary()（未入库时）→ set({ analysisPhase: 'splitting', analysisStep: 'storyboard', pendingDensity: density })
finishSplit: () => void         // 新：首次 → startSplit({ density: pendingDensity })；已入库增量 → confirmIncremental(pendingDecisions)；末尾 phase 'done'
```

`pendingDensity` / `pendingDecisions` 是两个 UI 态槽位，只在弹窗确认 → 动效跑完之间活着。

`AppShell` 的「跳过 ⏭」：`running = organizing || extracting || splitting`，分别调 `finishOrganize / finishExtract / finishSplit`。

### 5.3 新建一集（最简实现）

- `createBlankEpisode()`：往 `episodes` 末尾 push `{ id: 'e_manual_' + n, no: 下一号, title: '未命名', rawText: '', wordCount: 0, sceneIds: [] }`，自动展开并滚到视野内。

- 提取资产时手动集不产生候选；`fillDraftEpisodes` 给手动集建**一个**场（`name = 集名`，`rawText = 集正文`，`shotIds: []`），分镜表里这一场显示空态「本场还没有镜头，用「插入镜头」手动添加」（仓库已有就地插入镜）。

### 6.3 估算口径改成按字数（现在的 25 镜太少）

`cost.ts` 新增，**估值全部从字数推**，不再用 seed 的 3 场 25 镜当参照：

```ts
export const EST = {
  charsPerScene: 400,                                  // 每 400 字约 1 场
  charsPerShot: { compact: 24, standard: 30, loose: 40 },
  secPerShot:   { compact: '3–5', standard: '5–8', loose: '8–12' },
  rangeSpread: 0.08,                                   // 区间上限 = 下限 × 1.08
}
export function estimateScenes(words: number): number
export function estimateShotRange(words: number, dn: ShotDensity): [number, number]   // 取整到 5
```

4 800 字 → 约 12 场；标准 160–175 镜、紧凑 200–220、舒缓 120–130。价格不动（仍是 `costSplitByWords`：✦30 / ✦38 / ✦24；要调大改 `RATE.splitPerKChar` 一处）。
旧的 `estimateShots(sceneIds, density)` 保留给两个重拆弹窗（它们是对已有场重拆，按镜估合理）。

> 演示数据拆出来仍是 3 场 25 镜（seed 就这么多），和「预计 160 镜」对不上——这是演示品的已知取舍，弹窗里那行「生成前估算」的免责就是为此。以后 seed 扩了自然对上。

### 7.2 `StepBar` 三步

```ts
export const STEPS = [
  { n: 1, label: '整理剧本',     sub: ... 现状 },
  { n: 2, label: '确认资产清单', sub: () => '角色 / 服装 / 场景 / 道具' },
  { n: 3, label: '生成分镜脚本', sub: () => '拆场 / 拆镜 / 提示词' },
]
```

- `current`：visual 页 → 0；phase `organizing` 或 step episodes → 1；phase `extracting` 或 step assetConfirm → 2；phase `splitting` 或 step storyboard → **3**（有没有 shots、有没有 ready 提示词都是 3——这就是修「默认跳到生成提示词」那个问题）。
- `done`：1 = 任一集 extractedAt；2 = 已入库；3 = 全剧提示词就绪（allReady）。
- `jumpable`：1 = phase done；2 = 已入库或有候选；3 = 有 shots。动效跑着的时候（phase 非 done）三步都不可点。
- `jump(3)` 不再 `scrollToFooter`，删掉那个函数。
- `EmptyScriptState` 底部指引自动变三步（共用 `STEPS`）。
- 删掉 `n: 4` 相关的一切分支。
