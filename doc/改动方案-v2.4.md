## 一 · 本轮定下来的产品结论

### 1 · 主流程改成四步 + 一个出口

```
① 整理剧本（上传 / 拆集 / 校对） → ② 确认资产清单 → ③ 生成分镜脚本（拆场 / 拆镜） → ④ 生成提示词 → 去项目资产库生图
```

「去项目资产库生图」是下一模块的出口，不占步骤，只是分镜页页脚在全剧提示词就绪后的那个主按钮（已有）。

### 2 · 每一步的形态：一张页 + 右下角一个下一步。主线上零弹窗

| 步 | 页面 | 右下角主按钮 | 收费 |
|---|---|---|---|
| ① 整理剧本 | 集列表 + 集正文（新页 `EpisodeOrganize`） | `确认集数并提取资产 · ✦N` | 提取资产按字数收费；**上传、研读、拆集免费** |
| ② 确认资产清单 | 左按集原文 / 右候选清单（`AssetConfirm`） | `确认资产，进入拆分 →` | 免费（只是入库） |
| ③ 生成分镜脚本 | 还没拆：三张节奏卡的起点页（新页 `SplitStart`）；拆完：分镜表 | `开始拆分 · ✦N` / `生成提示词` | 拆分按字数 × 档位系数 |
| ④ 生成提示词 | 分镜表 | `去资产库生图 →` | 按镜收费（已有） |

**弹窗只留给三种情况：需要用户提供东西（选文件）、不可逆 / 高风险（删除、覆盖）、余额不足。** 其余一律不弹。
v2.3 的「预估中 → 确认花费弹窗」整段删除：它存在的理由是上传和付费之间没有可看的东西，
现在「整理剧本页」本身就是预估结果页——几集、多少字、多少钱，都在这一页，付费按钮就是确认。

### 3 · 拆集是自动结果，不是一个操作

选完文件直接进 3–5 秒 loading，跑完就是拆好的集。**不要出现「开始拆集」按钮。** 用户的任务不是操作拆集算法，是确认「这些集对不对」。

### 4 · 步骤③之前只有「集」这一个实体

步骤①、② 系统只认「集」。**不出现「共 3 场」「第 1 场」这类文案、编号、计数**，步骤条作用域文案也不提场。
原文里剧本作者自己写的场头（地点 · 时间）以视觉分块保留——那是排版，不是数据。场和镜头都在步骤③点「开始拆分」之后才产生。

### 5 · 锁是集级的，不是整页

参照小云雀：已经提取过资产的集在集标题旁带一把小锁 🔒，只读；新补充进来、还没提取的集没有锁，可以改名 / 合并 / 删除。
整理剧本页本身永远可以回去看，「补充剧本」永远可用（入口在页面右上角 ⋯ 里）。

### 6 · 补充剧本的节奏

⋯ → 补充剧本 → 选文件（这是一个弹窗，因为要选文件）→ 弹窗内 3 秒「整理中」→ 关闭，新集出现在列表末尾、带「新增」角标、无锁，
页脚变成 `提取第 N 集资产 · ✦N`。提取只针对新集；进步骤② 时已入库的资产灰显，只有新候选可操作。

### 7 · 重拆保留，但不再提取资产

重拆本场 / 重拆本集：从主工具栏撤下，只留在场 / 集的 ⋯ 菜单里。弹窗只有节奏选择 + 消耗，
资产检查区换成一行静态灰字 `✓ 本次将使用项目资产库中的现有资产，不新增。如需补充请到项目资产库添加。`（v2.3 §1.4，这句必须留）。

### 8 · 价格口径

- **提取资产 = 字数 × ✦/千字**，字数已知 ⇒ **确定值**，不给区间。
- **拆分 = 字数 × ✦/千字 × 档位系数**（紧凑 1.25 / 标准 1 / 舒缓 0.8）⇒ 也是确定值。
- **镜数**是估的 ⇒ 永远写「约 N 镜」或区间，不写假精确。
- 页脚不写「预计提取约 XX 项资产」——提取前编不出这个数。

## 二 · 数据模型与相位

**涉及文件**：`data/types.ts`、`store/useStore.ts`、`data/seed.ts`、`data/seedEpisode2.ts`

### 2.1 `Episode` 加三个字段

```ts
export interface Episode {
  id: string
  no: number
  title: string
  sceneIds: string[]        // 步骤③拆分前为 []
  rawText: string           // ★ 本集原文（步骤①②唯一的正文来源）。场头行以 "§ " 开头，渲染成小标题
  wordCount: number         // ★ 演示口径的字数（真产品数 rawText 长度；演示原文太短，直接给一个像样的数）
  extractedAt?: number      // ★ 提取过资产的时刻。有值 = 🔒 已锁；undefined = 新增未提取
}
```

- seed 里 `e1.rawText` = 三场原文按顺序拼接，每场前面插一行 `§ 客厅 · 周六 中午 12:00`（取 `location · timeOfDay`）。写个小函数在 `seed.ts` 里生成，别手抄。
- `e1.wordCount = 4800`；`seedEpisode2.ts` 的 `ep2Episode` 同样加 `rawText`（两场拼接）和 `wordCount = 3600`。
- `seedProject`（现状：已入库 + 有分镜）的 `e1.extractedAt = SEED_COMMITTED_AT`。
- `seedFreshProject` 改成：`episodes: [{ ...e1, sceneIds: [], extractedAt: undefined }]`，**`scenes: {}`**，`shots: {}`，`assets: {}`。这是「整理完毕、还没提取」的起点。
- `Scene` 类型不动。

- 「预计约 3 场」取 `Object.keys(seedProject.scenes).length`（演示里 seed 就是拆分结果，所以这是估值来源）。
- 点主按钮 → 卡片区原地换成 `TaskProgress`（`PHASES.split`，时长 `taskDuration(cost)`）→ `startSplit({ density })`。
- `PHASES.split` 改成：`正在划分场次` / `正在拆分镜头` / `正在生成分镜脚本`（**删掉「正在保存资产到项目资产库」**，入库在步骤② 已完成）。
- 有草稿集（补充过但没提取）时不该能到这页；不用拦，步骤条的 jumpable 规则会挡住（§七）。

### 5.3 `startSplit` 要创建场

现在的实现是 `for sid of seedProject.scenes: if (!scenes[sid]) continue`——它假设场已经存在，只往里填镜。改成：
对每个 `extractedAt` 有值且 `sceneIds` 为空的集，从 `seedProject.scenes` 取属于它的场（`episodeId` 匹配）**整个创建**（`shotIds` 按选定节奏填），并回写 `episode.sceneIds`。已经有场的集跳过（重拆走别的路）。挂载重指 `remapId` 逻辑不变。

## 八 · 计价

```ts
export const RATE = {
  extractPerKChar: 8,   // 提取资产：每千字 ✦8（演示口径，改这一处即可）
  splitPerKChar: 6,     // 拆分：每千字 ✦6
  shot: 1,              // 保留给重拆本场 / 本集（它们仍按镜数估）
  assetPrompt: 1,
  shotPrompt: 6,
}
export const DENSITY_COEF: Record<ShotDensity, number> = { compact: 1.25, standard: 1, loose: 0.8 }

export const costExtract = (words: number) => Math.max(1, Math.ceil(words / 1000) * RATE.extractPerKChar)
export const costSplitByWords = (words: number, dn: ShotDensity) =>
  Math.max(1, Math.round(Math.ceil(words / 1000) * RATE.splitPerKChar * DENSITY_COEF[dn]))
```
