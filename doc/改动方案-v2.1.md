## 0. 先说测试口径的调整

v2.0 里我把「每条规则配断言」写得太重了。产品口径这几周还在动，**手写断言的维护成本会超过它的价值**——口径一改，断言变成需要一条条改的负债。

本次起改成这样：

| 类型 | 处理 |
|---|---|
| `src/tests/rules.test.ts`（711 行，手写） | **冻结**。不再往里加新断言。口径变了就**删掉**对应的 `it`，不要花时间改它 |
| `src/tests/drills.test.ts`（22 行，`describe.each(DRILLS)`） | **保留**。它是数据驱动的：改口径只需改 `services/drills.ts` 里那一条，测试自动跟随，维护成本≈0 |
| 本次新增的能力 | **一条断言都不配**。验收方式是右下角速查面板点一遍 |

区别就一条：**数据驱动的断言几乎不要钱，手写的很贵。** 保留前者，不再增加后者。

`npm test` 在 Linux 上跑不起来（`node_modules` 是 macOS 装的，`rolldown` 原生绑定不匹配），在你机器上应该正常。不是代码问题，本次不处理。

## 1. 最要紧的一处：首次流程根本走不到阶段②

这个比你提的两条更严重，**优先级最高**。

`store` 的 `analysisStep` 初值是 `'storyboard'`（useStore.ts:421），而空态 → 上传 → 解析动画那条链（`App.tsx` 的 `useAnalysisReveal`）结束时只把 `analysisPhase` 置为 `'done'`，**没有人把 `analysisStep` 置为 `'assetConfirm'`**。

结果是：从「导入剧本」走进来，动画跑完直接落到分镜表。**阶段②（确认资产清单）在主路径上永远不出现**，只有调 `reuploadScript` 才能到。v3 整套「先资产、后脚本」的产品逻辑，在 demo 里看不见。

### 怎么改

**1.1 `data/seed.ts` 补一个未入库起点**

```ts
/** 首次导入的起点：只有集/场结构与原文，没有 shots，资产全在候选里。 */
export const seedFreshProject: Project   // libraryCommittedAt: null, shots: {}, assets: {}
export const seedCandidates: CandidateAsset[]
```

`seedCandidates` 的 `tempId` 继续沿用 seed 资产 id（`startSplit` 的 `remapId` 已经依赖这个约定，别破坏）。

**1.2 `store` 加 `finishFirstImport()`**

```ts
/** 解析动画跑完 → 落到阶段② 完整确认页。 */
finishFirstImport: () => set({
  project: structuredClone(seedFreshProject),
  candidates: seedCandidates,
  analysisStep: 'assetConfirm',
  activeTab: 'character',
  promptStates: {},
  promptEdited: {},
}),
```

**1.3 `App.tsx` 的时间线控制器接上**

`analyzing` 分支里 `DONE_AT` 那个 `at()` 现在是：

```ts
at(DONE_AT, () => { setTab('shot'); setPhase('done') })
```

改成：

```ts
at(DONE_AT, () => { finishFirstImport(); setPhase('done') })
```

`reduce`（减弱动态）分支同理。

**1.4 `replayDemo` 一并复位**

现在它只复位 `analysisPhase`。要加上 `analysisStep: 'storyboard'`、`candidates: []`、`pendingTask: null`，否则「重新演示」之后状态是串的。

**1.5 解析动画的第四步文案**

`services/analysisTimeline.ts` 的 `checklist` 最后一步是「提取角色 · 服装 · 场景 · 道具」，正好就是阶段②要确认的东西，不用改。但 `EmptyScriptState.tsx` 里那三步指引（`{ n: '3', title: '生成提示词', sub: '进资产库生图' }`）已经和五步流程对不上了，改成与 §2 的 `STEPS` 同一份数据。

> **注意**：默认起点变了之后，进站第一眼是空态 → 导入 → 阶段②。要直接看分镜表调试，走「重新演示」右边加一个隐藏入口，或临时把 `analysisStep` 初值改回 `'storyboard'`。不要为此加 UI 开关。

## 2. 五步流程条（你截图里的那个）

仓库里**完全没有**。这是演示时最重要的一块——它既是导航，也是「现在走到哪一步」的说明。

### 2.1 新组件 `src/components/StepBar.tsx`

```tsx
// 剧本分析的五步流程条。既是进度指示，也是演示用的跳转入口。
// 可跳的上限由数据决定：未入库只能到②，入库后到③，有提示词后到④。
const STEPS = [
  { n: 1, label: '导入剧本',     sub: (p) => `${p.episodes.length} 集` },
  { n: 2, label: '确认资产清单', sub: () => '全剧' },
  { n: 3, label: '生成分镜脚本', sub: () => '集 / 场 / 镜' },
  { n: 4, label: '生成提示词',   sub: () => '' },
  { n: 5, label: '资产库生图',   sub: () => '' },
]
```

**状态推导**（不要新加 state，全从现有数据算）：

| 步 | current 条件 | 可跳条件 |
|---|---|---|
| ① | `analysisPhase !== 'done'` | 恒可跳（= `replayDemo()`） |
| ② | `analysisStep === 'assetConfirm'` | 恒可跳（入库后仍可回看，只读） |
| ③ | `analysisStep === 'storyboard' && activePage === 'analysis'` | `libraryCommittedAt != null && shots 非空` |
| ④ | 同③但有 `ready` 提示词 | 同③ |
| ⑤ | `activePage === 'visual'` | 全部提示词 ready（沿用 `ScriptAnalysis` 已算好的 `allReady`） |

④和⑤在本仓库里不是独立页面（④是分镜表里的生成动作，⑤是 `VisualPrep`），所以点④=跳到分镜表并滚到页脚 CTA，点⑤=`setPage('visual')`。**这一点要在代码注释里写清楚**，否则后面会有人以为漏做了两个页面。

### 2.2 作用域标签

原型里流程条右侧有一条 `当前作用域 整本剧本 · 集/场/镜在第③步产生`。这条信息很值钱——它是回答「为什么这一步没有集场镜」的地方。照抄口径：

- 阶段② → `当前作用域 整本剧本 · 集 / 场 / 镜在第 ③ 步产生`
- 阶段③ → `当前作用域 第 N 集 · 第 M 场`

### 2.3 放哪儿

`AppShell` 的主内容区顶部，`activePage === 'analysis'` 时才渲染。不要塞进 `AssetConfirm` 或 `ScriptAnalysis` 各写一份——两个页面都要用，写两份必然漂移。

样式沿用 `theme.css`：当前步 `--acc` 描边 + `--acc-bg` 底；已完成步 `--t3` + ✓；不可跳步 `--t5` + `disabled`。

## 3. 阶段② 的悬浮联动高亮

`AssetConfirm.tsx` 的 `highlight()` 现在是**静态全量着色**——所有实体一直亮着。缺的是：**hover 某一条候选 → 左侧原文只把它的名字点亮，其余实体压暗**。

这是让人相信「这份清单真的来自整本剧本」最直接的证据，演示时价值很高。

### 3.1 与仓库既有设计原则的关系（要先说清楚，否则会被驳回）

`components/EntityText.tsx` 的注释里明确写着：

> 高亮只往「出场的人和物」去，不往左边「本场剧本」去 —— 原文面板是彩色区，它自己已经在标实体了，再叠一层联动高亮就是噪音。

**这条规则是为阶段③ 写的，不适用于阶段②**，理由：

- 阶段③ 的右侧有「出场的人和物」那一列可以承接高亮，阶段② 没有那一列，联动无处可去
- 阶段③ 的左栏是**本场**原文（十几段），阶段② 是**全剧**原文（几十上百段），后者不联动就根本找不到
- 阶段② 的核心疑问是「这一条是从哪儿抽出来的」，联动就是答案

在 `AssetConfirm` 的高亮实现旁把这段理由写进注释，避免后面有人按 `EntityText` 的注释把它删掉。

### 3.2 实现

**不要复用 `hoverMention`**——那个带 `shotId`，阶段② 没有镜头。新加一个：

```ts
// store
/** 阶段② 悬浮到某条候选/已入库资产时，左侧原文点亮它的名字。
 *  与 hoverMention 是两回事：那个带 shotId、服务分镜表；这个只有资产身份。 */
hoverAssetTerm: { terms: string[] } | null
setHoverAssetTerm: (t: { terms: string[] } | null) => void
```

`terms` 直接存名字数组（`[name, ...aliases]`），因为阶段② 的候选没有稳定 id 可供左栏反查，用名字最直接。

**高亮的三档表现**（按你定的口径：只亮名字，不压整段）：

```css
/* 默认：静态类目色，维持现状 */
.hl { color: var(--…kind…); }
/* 有 hover 时，非命中项压暗 —— 让目标成为唯一亮的东西 */
.hovering .hl:not(.on) { opacity: .3; }
/* 命中项：加描边 + 光晕 + 加粗，不给整段加底色 */
.hovering .hl.on { font-weight: 600; outline: 1px solid var(--acc); outline-offset: 1px;
                   box-shadow: 0 0 0 3px rgb(var(--acc-rgb) / .16); }
```

**不要**做原型早期那版「整段压暗 + 命中段加底色」——你已经否过一次了，段落一多就太亮。

**滚动**：hover 时不滚。只有点击那一行才 `scrollIntoView({block:'center'})` 到首现位置。hover 就滚会晕。

### 3.3 顺带补出场列

候选行现在显示 `全剧 N 处 · 首现第 X 段`，但 `occCount` / `firstParaNo` 是抽取时算的静态值，且**不可点**。加上点击定位（点一下滚到首现段并短暂闪一下），和 `jumpToAppearance` 是同一种交互，只是目标从镜头换成原文段。

## 4. 三处「做了一半」的接线

### 4.1 「重新上传剧本」按钮是占位

`AssetConfirm.tsx` 页脚：

```tsx
onClick={() => canReupload ? showToast('重新上传：请从空态点「导入剧本」重来（演示占位）') : undefined}
```

而 `store.reuploadScript(payload)`（useStore.ts:1126）**已经实现好了**。只差接线：

```tsx
onClick={() => setReuploadOpen(true)}
```

补一个确认弹窗 `ReuploadDialog`（复用 `ConfirmPromptDialog.module.css` 的骨架），文案照原型：

> 当前这 N 项一条都还没写进项目资产库，分镜也还没生成，所以整本替换是零副作用的。
> **一旦点过「确认并保存到项目资产库」，这个入口就没有了**——那之后要换一部剧本，请新建项目。

确认后调 `reuploadScript(altScriptPayload)`。

### 4.2 「当前剧本未引用」在界面上一处都没用

`services/reference.ts` 的 `refState` / `unreferencedCount` 写好了、`rules.test.ts` 也测了，但 `grep` 全仓库**没有任何 UI 引用它们**。

这条口径（删场删集不删资产，只变成未引用）是这次改动最核心的产品判断之一，看不见等于没做。要挂三个地方：

| 位置 | 表现 |
|---|---|
| `AssetRow` 状态列 | 已入库且 `refState === 'unreferenced'` → 名称下加一行弱化黄字 `当前剧本未引用` |
| `AssetOverviewBar` | 有未引用项时追加 `· N 项当前剧本未引用` |
| `deleteScene` / `deleteEpisode` 的 toast | 已经在 v2.0 里改过文案，核对一下 `K` 的计算是否真的接了 `unreferencedCount` |

### 4.3 阶段② 清单比原型少了四样

按重要性排序，前两样建议做，后两样可选：

| 缺的 | 值不值得 |
|---|---|
| **提示词列 + ✦ AI 结合剧本补全** | **值**。手动补录的候选现在只有名字没有提示词，补全按钮是原型里最能说明「清单不是死表」的交互 |
| **角色行的造型 chips + ＋服装** | **值**。P3 做了 `LookMountControl` 但只挂在 `AssetRow`（阶段③），阶段② 的候选行没有。造型手动挂载是这次拍板推翻旧决议的那一条，应该在确认清单里就能看见 |
| 搜索框 | 可选。19 项的演示数据用不上，集数多了才有用 |
| 排序（按出现次数 / 首现顺序） | 可选。同上 |

## 5. 顺手要修的两处小问题

**5.1 `startSplit` 忽略了参数**

签名是 `startSplit(opts: { density?, instant? })`，实现是 `startSplit: (_opts) => {...}`——参数完全没用，永远按 seed 的标准分镜生成。

阶段② 的「开始拆分集/场/镜」按钮按 v3 §9.1 应该先弹算力确认（范围 / 预计消耗 / 预计耗时 / 本次不含提示词），并让用户选颗粒度。现在直接就跑了。

建议：复用已有的 `ResplitSceneDialog` 的颗粒度选择器做一个 `StartSplitDialog`，把 `density` 真的传下去。`instant` 保留给 drills 用。

**5.2 `AssetConfirm` 已入库行的「出场」列写死了「已入库」**

```tsx
<span className={s.occ}>已入库</span>
```

出场列显示「已入库」、状态列也显示「已入库」，同一个信息占了两列。已入库项的出场应该显示真实的引用情况（`refState` 或镜头数），或者干脆留空。

| 序 | 内容 | 为什么这个顺序 |

## 7. 不建议做的

- **不要**把原型的五步流程条做成可以自由乱跳。跳转上限必须由数据决定（未入库跳不到③），否则会跳到一个自相矛盾的状态，演示时更尴尬。
- **不要**为了阶段② 的联动去改 `EntityText`。那是阶段③ 的组件，两边的信息结构不一样，共用一套只会互相拖累。
- **不要**在阶段② 引入集/场/镜口径。已入库行的出场也只能用原文口径或镜头数，不要写「1 集 3 场 24 镜」——阶段② 还没有镜。
