## 1. 数据模型改动

### 1.1 新增 UI 态：`promptEdited`

**文件**：`src/store/useStore.ts`

`promptStates` 保持四态不变（`pending / generating / ready / stale`），**另加一个独立维度**记录「这一镜的提示词被手动编辑过」。两者不是一个枚举，不要合并。

```ts
// StoreState 里，紧跟 promptStates 声明
/** 镜头提示词是否被手动编辑过。与 promptStates 是两个正交维度：
 *  一个镜头可以同时是「已手动编辑」和「待更新」。UI 态，不进 Shot 数据模型。 */
promptEdited: Record<string, boolean>

markPromptEdited: (shotId: string) => void
```

写入与清除时机：

| 时机 | 行为 |
|---|---|
| 用户在 `ShotPromptDialog` 手动改写了 image/video 提示词并保存 | `promptEdited[shotId] = true` |
| `generatePrompts(ids)` 执行到某镜 | 该镜 `promptEdited[shotId] = false`（重新生成即覆盖，手动痕迹消失） |
| 新增镜头 / 替换本集 / 重拆 | 相关镜头的 `promptEdited` 一并清掉，不要留孤儿键 |

`initPromptStates` 旁边加一个 `initPromptEdited(project)` 返回空对象即可，但**所有重建 `promptStates` 的地方都要同步重建 `promptEdited`**（替换本集、重拆本集/本场、追加剧集、删除集/场/镜）。

### 1.2 新增纯函数模块：`src/services/promptScope.ts`

范围求解与默认勾选是会错的规则，按仓库「逻辑内核优先」的方针写成不碰 UI 的纯函数，并配测试。

```ts
// 规则版本：v1.3（2026-08-15）。断言见 tests/promptScope.test.ts 的 R14。
export type PromptScope = 'scene' | 'episode' | 'project'

/** 求某范围内的全部镜头 id，按「集 → 场 → 镜」自然序返回。 */
export function shotIdsOfScope(
  project: Project,
  scope: PromptScope,
  sceneId: string,
): string[]

/** 默认勾选规则：pending / stale 勾选，ready 不勾选，generating 不勾选且不可选。 */
export function defaultSelection(
  ids: string[],
  states: Record<string, PromptState>,
): Set<string>

/** 把范围内镜头按「集 → 场」分组，供弹窗渲染。 */
export function groupByScene(
  project: Project,
  ids: string[],
): Array<{ episodeNo: number; sceneId: string; sceneNo: number; sceneName: string; shotIds: string[] }>
```

### 1.3 新增纯函数：资产替换 diff

**文件**：`src/services/replace.ts`

```

「模拟拆解失败」链接是 demo 专用触发器，用 `s.demoHint` 类弱化到几乎不可见（与仓库里其他 demo 提示同级），头注写明用途。

### 3.6 第三步 · 拆解中（`running`）

**关键约束：先拆解成功，再落库。拆解期间原剧集内容不得有任何变化。**

```

［ 转圈 ］ 正在拆解新剧本…原第 {no} 集内容暂未改动

无按钮（不可关闭，不可点遮罩）
```

Demo 固定耗时 **1200ms**，`setTimeout` 实现。

> **⏳ 待定（等开发确认后再定）**：真实拆解耗时若超过 10 秒，这里需要改成「允许关闭弹窗、后台拆解、完成后通知」。本次先按阻塞式实现，把 1200ms 抽成一个具名常量 `MOCK_PARSE_MS`，方便后续替换。

### 3.7 结果

**成功** → 关闭 dialog，落库，弹 toast（数字来自 `episodeReplaceDiff`）：

```
第 {no} 集已替换为 {n} 场 {n} 个镜头。沿用已有资产 {reused} 项，新增 {added} 项，移除 {removed} 项。

**失败** → 停在 dialog 内，红字 + 两个按钮：

```
⚠ 新剧本拆解失败，原第 {no} 集未发生变化。

按钮：［取消］［重试］
```

`store.replaceEpisode(episodeId)` 保持现有签名与行为，只在其外层包装上述流程；diff 统计在调用前后各取一次 `project` 交给 `episodeReplaceDiff`。

- 右侧显示该场 `已选 x/y`

2. **状态标记**（见 6.5）

### 6.5 镜头状态与默认勾选

**两个正交维度，不要合并成一个枚举。**

维度一 · 提示词状态（互斥，来自 `promptStates`）：

| 状态 | 行内标记 | 默认勾选 |
|---|---|---|
| `pending` 未生成 | `未生成`（灰） | ✅ |
| `stale` 待更新 | `⚠ 待更新`（黄） | ✅ |
| `ready` 已生成 | `已生成`（灰，整行弱化） | ⬜ |
| `generating` 生成中 | `生成中…` | ⬜ 且 disabled |

维度二 · 来源标记（独立布尔，来自 `promptEdited`）：为 true 时在状态标记右侧加一个小角标 **`✎ 手动`**，`title="提示词经过手动编辑"`。这个角标可以和上面任意一个状态共存。

**交互反馈**：

- 用户勾选一个 `ready` 的镜头 → 该行状态标记变为 **`将重新生成`**
- 用户勾选一个带 `✎ 手动` 的镜头 → 该行下方展开一行黄色提示：
  `该镜头的提示词经过手动编辑，重新生成将覆盖当前内容。`
  （挂在 ✎ 标记上，不挂在某个状态上——这样「手动编辑过 + 待更新」这个组合天然就是「默认勾选 + 给覆盖提示」）

### 6.6 底部

- 左侧保留 `全选镜头` + `已选 {n}/{total}`，作用域为**当前范围内全部镜头**
