## 一 · 本轮定下来的产品结论

这一节不用写代码，是后面所有判断的依据。

### 1 · 拆分节奏怎么显示

不管是全剧首拆、重拆本集、还是重拆本场，都给三档：**紧凑 / 标准 / 舒缓**。

三档卡片上放三样东西，按这个优先级：

1. **创作效果**（主文案）——用户真正据此做选择
2. **平均 N 镜/场**（数量感）——这个单位在全剧、本集、本场三个尺度上通用
3. **星钻价**——三档不同价

```
选择全剧默认镜头节奏
全剧预计 12 集 · 48 场 · 3.2 万字

┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│     紧凑      │ │     标准      │ │     舒缓      │
│ 高频切镜，动作 │ │ 叙事、动作与情 │ │ 长镜头更多，保 │
│ 对白推进更快   │ │ 绪留白相对均衡 │ │ 留表演和发酵   │
│              │ │              │ │              │
│ 平均 8 镜/场   │ │ 平均 6 镜/场   │ │ 平均 5 镜/场   │
│    ✦340      │ │    ✦280      │ │    ✦230      │
└──────────────┘ └──────────────┘ └──────────────┘

预计约 260–300 镜 · 预计耗时 6 分钟 · 已有资产及图片不受影响
```

三条硬规则：

- **集数、场数不随档位变。** 节奏决定的是场内怎么切镜，不改变剧本的结构划分。三个档位的"12 集 48 场"是同一个数字，所以它放在顶部只说一次，不进卡片。
- **总镜数用区间**（`约 260–300 镜`），因为生成前只能估。不要写"300 镜"这种假精确。
- **总镜数是弱信息**，放在卡片下方的汇总行，不放卡片标题。用户对 300 和 250 的差别没有感知能力，对"平均 8 镜/场"有。

### 2 · 拆分怎么计价

**价格按字数算，不按镜数算。**

因为镜数是估的，按镜数计价就意味着按钮上写 `✦280`、实际扣 `✦340`，等于让用户授权一笔没有上限的费用。

```
拆分价格 = 字数 × 基础单价 × 档位系数
```

- 字数是已知的 → **价格是确定值**
- 档位系数保证三档价格不同（紧凑最贵）
- 镜数继续显示区间

**该确定的是钱，该模糊的是镜数。现在的设计正好反了。**

### 3 · 重拆本场、重拆本集都保留

两个都留，都给三档节奏。理由：首次只能给全剧选一个默认节奏，但真实创作一定会出现"动作场想更紧凑、情绪场想更舒缓"。如果不能重拆，全剧第一次的选择就变成近乎不可逆的决定，对生成式产品风险太大。

### 4 · 重拆不重新提取资产

**统一规则：原文不变，只重拆镜头；原文发生新增或替换，才做增量资产检查。**

| 操作 | 原文变了吗 | 查不查新资产 |
|---|---|---|
| 重拆本场 / 重拆本集 | 没变 | **不查** |
| 导入后续剧本 / 新增有文本的场 / 替换本集或本场文本 | 变了 | 查 |
| 插入空白场、改镜头字段、重命名 | 没变 | 不查 |

重拆时如果用户觉得资产提漏了，去项目资产库手动新增，再回镜头里 `@`。

**但重拆弹窗里那句话要留着**：

> ✓ 本次将使用项目资产库中的现有资产，不新增。如需补充请到项目资产库添加。

不是走过场。不说这句，用户会怀疑系统到底看没看资产库。**删掉的是"发现新资产"这个行为，不是"我们看过资产库"这句话。**

### 5 · 资产确认永不反向跳转

任何操作都不许把用户送回步骤②。

理由是硬的：步骤②那一页在定义上是"全剧首次资产确认"——左边全剧原文、右边全剧十几项。为了 3 个新资产把用户送回去，他会以为要重新确认全部。那是把一个专用页面当通用页面用。

新资产一律在**当前任务的弹窗里**确认完，确认完接着跑。

### 6 · 导入后续剧本放在第三步

入口在分镜表页面的剧集树顶部或末尾：`＋ 添加剧集 / 导入后续剧本`。

用户产生这个需求时正在看分镜，心智是"继续给这个项目加内容"，不是"重走一遍首次导入"。点击后在同一个弹窗里连续走完：导入 → 解析新增集/场 → 确认本次新增资产 → 选节奏 → 生成。

（本轮不实现，先把口径记下来。）

## 二 · 步骤一：上传剧本

**涉及文件**：`pages/EmptyScriptState.tsx`、`store/useStore.ts` 的上传相关状态

### 现在是什么样

空态页上一个按钮 `＋ 解析剧本 · ✦N`，点了直接开始解析，中间没有任何确认。价格是在用户还没上传任何东西的时候就算出来的——这不对，没拿到剧本怎么估价。

### 改成什么样

用户看到的完整节奏，四拍：

**第一拍 · 上传**

按钮文案改成 **`＋ 上传剧本`**。上面不带价签——这时候还不知道要花多少钱。

副文案：`支持 txt / docx / fdx`（把"按字数计费"去掉，价格在第三拍才出现）

**第二拍 · 系统预估（3–5 秒）**

点击后进入一个**预估中**的状态，停 3 到 5 秒。这不是性能问题，是要让用户看见系统在读他的剧本。

界面上是一个轻量的加载态（复用 `TaskProgress` 就行，不用整页动画），文案分两段走：

```
⟳ 正在读取《最后的尊严》…
⟳ 正在预估拆解与资产提取的消耗…
```

**第三拍 · 确认花费弹窗**

预估完，弹一个小弹窗：

```
┌─────────────────────────────────────────┐
│  确认解析剧本                             │
│                                          │
│  《最后的尊严》· 3.2 万字                  │
│  预计拆出 12 集 · 48 场                    │
│                                          │
│  是否确认拆解并提取该剧本中的                │
│  所有角色、服装、场景、道具，并生成提示词？    │
│                                          │
│  本次消耗 ✦100                            │
│  本次只提取资产，暂不拆分镜头                │
│                                          │
│         [取消]      [确认解析 · ✦100]      │
└─────────────────────────────────────────┘
```

- 取消 = 回到空态，什么都没发生
- 那句"本次只提取资产，暂不拆分镜头"要有，否则用户以为 ✦100 买的是全套

**第四拍 · 进入步骤二**

点确认后才真正开始解析，走完进步骤②。

## 三 · 步骤二：确认资产清单

**涉及文件**：`pages/AssetConfirm.tsx` + `.module.css`、`pages/AnalyzingWorkspace.tsx`
**规格来源**：`资产清单确认-原型_2.html`（**是规格不是代码源，色值一个都不要抄，只用 `theme.css` 变量**）

### 3.1 这一页只做这一页的事

现在从步骤一进来会走 `AnalyzingWorkspace` 的分阶段揭示，把集场目录、分镜表、Storyboard 一样样铺出来——**那是仓库早期演示留下的，跟步骤二没有关系。**

步骤二这时候还没有集、场、镜，展示分镜脚本是错的。

改成：解析结束后**直接进步骤②的页面**，左边全剧原文，右边资产清单，没有别的。`AnalyzingWorkspace` 只留给第二拍那个预估/解析过程，或者干脆不用它。

### 3.2 中缝可拖拽

左边原文栏和右边资产栏中间那条竖线，鼠标悬浮时变成拖拽手柄，可以左右拉宽度。

仓库里已经有 `components/PanelResizer.tsx`，直接复用，不用新写。

### 3.3 表格只留三列

现在是：`色点 | 名称+提示词 | 状态 | 操作`，名称下面还挂着一行 `全剧 7 处 · 首现第 12 段`。

**「在剧本中出现」这一列和那行小字全部删掉。**（原型 2 里那一列也删了）

改成：

```
色点 | 名称 | 生成提示词 | 状态 | 操作
```

- 名称列：只有名字（角色行额外带造型开关，见 3.5）
- 生成提示词列：预览一行，点开是浮层（见 3.4）
- 状态列：待入库 / 已入库 / 未引用
- 操作列：🗑

顺带删掉的：`locate()` 那套"点小字定位原文"的交互跟着这一列一起走。**hover 整行点亮左边原文里的名字这个联动要保留**，那个很好用。

### 3.4 提示词点开是浮层，不是行内展开

现在点提示词是行内展开一个 textarea，把行撑高——行高和列宽一直在变，看着很晃。

改成：**点击提示词 → 弹出一个浮层，盖在整个数据区上方。**

```
┌───────────────────────────────────┐
│  苏可 · 生成提示词                   │
│  ┌─────────────────────────────┐   │
│  │ （多行文本，可编辑）           │   │
│  │                             │   │
│  └─────────────────────────────┘   │
│  ✦ AI 结合剧本补全 · ✦1             │
│              [取消]      [保存]     │
└───────────────────────────────────┘
```

- 浮层固定尺寸，不随内容变
- 底下的数据行完全不动
- 仓库里有 `components/PromptDialog.tsx`，能复用就复用

### 3.5 名字双击改，造型点开带出提示词和状态

**名字**

- 删掉名字右边那个小铅笔 `✎`
- 改成**双击名字**直接进入编辑，回车保存，Esc 取消
- 名字右边不放任何类型标签（角色/服装/场景/道具的字样）——类型靠最左边的色点表达就够了
- 列表顶部那四个分类 tab（角色 6 / 服装 5 / 场景 4 / 道具 4）**保留**，那是分类导航，原型里也有

**造型**

角色行右边保留 `3 套造型 ⌄` 和 `＋ 服装`。

点开之后，每套造型是一条子行，靠一条竖直连接轨归属到上面的角色。**子行要把这套造型自己的「生成提示词」和「状态」一起带出来**，跟主行的列对齐：

```
苏可                    米灰燕麦色 oversize 卫衣…        待入库    🗑
  │
  ├─ 苏可 · 宽松连帽卫衣   苏可素模 + 宽松连帽卫衣的融合…   待入库   ⇄ 🗑
  └─ 苏可 · 通勤西装       苏可素模 + 通勤西装的融合造型…   待入库   ⇄ 🗑
```

- 造型名 `角色 · 服装` 自动拼，不单独改名
- 造型的提示词也是点开浮层编辑，跟主行同一个交互
- 造型没有出现次数（本来就跟着角色走）

## 四 · 点一遍就算验收

不写测试。跑起来照着点：

1. 空态按钮写的是 `＋ 上传剧本`，**上面没有价签**
2. 点了之后有 3–5 秒的预估过程，能看到文案在走
3. 预估完弹出确认弹窗，上面有字数、预计集场数、`✦100`、和"暂不拆分镜头"那句
4. 点取消 → 回空态；点确认 → 才开始解析
5. 解析完直接进资产清单页，**左原文右资产，看不到任何分镜脚本或集场目录**
6. 中缝能拖，左右宽度会变
7. 表格里没有"在剧本中出现"那一列，名称下面也没有小字
8. 双击名字能改，名字右边没有铅笔、没有类型标签
9. 点提示词弹浮层，底下的行一动不动
10. 角色行点 `3 套造型 ⌄`，子行带着自己的提示词和状态出来
